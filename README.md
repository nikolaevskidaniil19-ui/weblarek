# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

Стек технологий: HTML, SCSS, TS, Vite

## Структура проекта
- `src/` — исходные файлы проекта
- `src/components/` — папка с JS компонентами
- `src/components/base/` — папка с базовым кодом

### Важные файлы:
- `index.html` — HTML-файл главной страницы
- `src/types/index.ts` — файл с типами
- `src/main.ts` — точка входа приложения
- `src/scss/styles.scss` — корневой файл стилей
- `src/utils/constants.ts` — файл с константами
- `src/utils/utils.ts` — файл с утилитами

## Установка и запуск

Для установки зависимостей выполните команду:

```bash
npm install
```

или при использовании yarn:

```bash
yarn
```

Для запуска проекта в режиме разработки (dev-сервер):

```bash
npm run dev
```

или:

```bash
yarn dev
```

## Сборка

Для сборки проекта в продакшн выполните команду:

```bash
npm run build
```

или:

```bash
yarn build
```

## Типы и интерфейсы данных

В приложении используются строго определенные типы и интерфейсы TypeScript, описывающие структуру моделей данных, контракты сетевого взаимодействия и типы ошибок валидации.

### Базовые типы и интерфейсы

#### Интерфейс IProduct
Описывает структуру отдельной карточки товара (продукта) в магазине.
- `id: string` — уникальный идентификатор товара.
- `title: string` — название товара.
- `category: string` — категория товара.
- `image: string` — относительный путь или URL к изображению товара.
- `description: string` — подробное текстовое описание товара.
- `price: number | null` — стоимость товара в условных единицах.

#### Интерфейс ICustomer
Описывает структуру данных профиля покупателя, собираемых в процессе оформления заказа.
- `payment: TPayment | null` — выбранный способ оплаты (`online` или `onReceipt`), либо `null`, если способ оплаты ещё не выбран.
- `address: string` — адрес доставки товара.
- `email: string` — адрес электронной почты клиента.
- `phone: string` — контактный телефон клиента.

#### Тип TPayment
Определяет допустимые значения для способов оплаты. Является объединением строковых литералов: `'online'`, `'onReceipt'` или `null`.

#### Интерфейс TOrder
Расширяет интерфейс `ICustomer`, представляя собой полную структуру оформляемого заказа, отправляемую на сервер.
- Наследует все поля `ICustomer`.
- `items: string[]` — массив уникальных ID (`id`) товаров, которые пользователь приобретает.
- `total: number` — итоговая стоимость всех товаров в заказе.

### Типы ответов сервера и ошибок

#### Тип TProductListResponse
Описывает структуру ответа сервера при запросе списка всех доступных товаров.
- `items: IProduct[]` — массив объектов товаров, доступных для отображения в каталоге.
- `total: number` — общее количество товаров на сервере.

#### Тип TOrderResponse
Описывает структуру успешного ответа сервера после успешной отправки и обработки заказа.
- `id: string` — уникальный идентификатор созданного на сервере заказа.
- `total: number` — подтвержденная сервером итоговая стоимость заказа.

#### Тип TCustomerErrors
Тип для хранения ошибок валидации полей профиля покупателя. Представляет собой объект, ключами которого могут быть поля интерфейса `ICustomer`, а значениями — строки с текстом ошибок.

### Интерфейсы коммуникационного слоя

#### Интерфейс IApi
Описывает контракт для низкоуровневого сетевого клиента (базового класса `Api`). Используется для типизации параметра конструктора в классе-адаптере `WebLarekApi.ts`.
- `get<T extends object>(uri: string): Promise<T>` — generic-метод для отправки HTTP GET-запроса.
- `post<T extends object>(uri: string, data: object, method?: ApiPostMethods): Promise<T>` — generic-метод для отправки HTTP-запросов, изменяющих состояние (`POST`, `PUT`, `DELETE`).

#### Тип ApiPostMethods
Определяет перечень доступных HTTP-методов для изменения данных на сервере. Допустимые значения: `'POST' | 'PUT' | 'DELETE'`.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

- **Model** — слой данных, отвечает за хранение и изменение данных.
- **View** — слой представления, отвечает за отображение данных на странице.
- **Presenter** — презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса. 
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

**Конструктор:**
- `constructor(container: HTMLElement)` — принимает ссылку на DOM элемент за отображение, которого он отвечает.

**Поля класса:**
- `container: HTMLElement` — поле для хранения корневого DOM элемента компонента.

**Методы класса:**
- `render(data?: Partial<T>): HTMLElement` — Главный метод класса. Принимает данные для отображения в интерфейсе, записывает их в поля класса и возвращает ссылку на DOM-элемент.
- `setImage(element: HTMLImageElement, src: string, alt?: string): void` — утилитарный метод для модификации DOM-элементов `<img>`.

#### Класс Api
Содержит в себе базовую логику отправки запросов.

**Конструктор:**
- `constructor(baseUrl: string, options: RequestInit = {})` — в конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

**Поля класса:**
- `baseUrl: string` — базовый адрес сервера.
- `options: RequestInit` — объект с заголовками, которые будут использованы для запросов.

**Методы класса:**
- `get(uri: string): Promise<object>` — выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объект, которым ответил сервер.
- `post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` — принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт. По умолчанию выполняется `POST` запрос.
- `handleResponse(response: Response): Promise<object>` — защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными или отклоненный промис.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

**Конструктор:**
- `constructor()` — конструктор класса не принимает параметров.

**Поля класса:**
- `_events: Map<string | RegExp, Set<Function>>` — хранит коллекцию подписок на события. Ключи коллекции — названия событий или регулярное выражение, значения — коллекция функций обработчиков.

**Методы класса:**
- `on<T extends object>(event: EventName, callback: (data: T) => void): void` — подписка на событие, принимает название события и функцию обработчик.
- `emit<T extends object>(event: string, data?: T): void` — инициализация события. При вызове события в метод передается название события и объект с данными.
- `trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` — возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие.

### Слой данных (Компоненты моделей данных)

#### Класс Cart
Отвечает за хранение добавленных в корзину товаров, подсчет их общего количества и стоимости. Для оптимизации поиска и удаления товаров вместо классического массива используется структура ассоциативного объекта-карты (`Record`).

**Конструктор:**
- `constructor()` — инициализирует пустое внутреннее хранилище в виде объекта без прототипа. Не принимает входящих параметров.

**Поля класса:**
- `_storage: Record<string, IProduct>` — внутреннее хранилище, где ключами являются id товаров, а значениями — сами объекты продуктов.

**Методы класса:**
- `getItems(): IProduct[]` — собирает и возвращает массив всех товаров, извлекая их из объекта-хранилища.
- `addItem(item: IProduct): void` — добавляет товар в корзину под его уникальным id, если его там еще нет.
- `removeItem(id: string): void` — удаляет товар из корзины по id с использованием оператора `delete`.
- `clear(): void` — полностью очищает корзину, сбрасывая хранилище до пустого объекта.
- `getTotal(): number` — итерирует по позициям в корзине и возвращает суммарную стоимость товаров.
- `getItemsCount(): number` — возвращает число уникальных товаров в корзине.
- `checkItem(id: string): boolean` — проверяет наличие товара в корзине по его id.

#### Класс Catalog
Отвечает за сохранение и обработку списка доступных товаров витрины магазина, а также хранение информации о выбранном для просмотра продукте.

**Конструктор:**
- `constructor()` — инициализирует пустой массив товаров и сбрасывает выбранный активный элемент в `null`. Не принимает входящих параметров.

**Поля класса:**
- `_goodsList: IProduct[]` — массив всех доступных для покупки товаров.
- `_currentActiveItem: IProduct | null` — объект товара, который в данный момент выбран (открыт в модальном окне), или null.

**Методы класса:**
- `getItems(): IProduct[]` — возвращает новый массив-копию всех товаров каталога.
