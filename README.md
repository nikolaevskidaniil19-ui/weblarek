# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модающими окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

Стек технологий: HTML, SCSS, TS, Vite

## Структура проекта
- `src/` — исходные файлы проекта
- `src/components/` — папка с JS компонентами
- `src/components/base/` — папка с базовым кодом
- `src/components/models/` — папка с классами моделей данных (слой Model)
- `src/components/view/` — папка с компонентами интерфейса и формами (слой View)

### Важные файлы:
- `index.html` — HTML-файл главной страницы
- `src/types/index.ts` — файл с типами
- `src/main.ts` — точка входа приложения и слой управления (Presenter)
- `src/scss/styles.scss` — корневой файл стилей
- `src/utils/constants.ts` — файл с константами
- `src/utils/utils.ts` — файл с утилитами

## Настройка окружения
Приложение взаимодействует с внешним сервером. Перед запуском проекта создайте в корневой директории файл `.env` и укажите базовый URL для API:
```env
VITE_API_ORIGIN=https://имя-вашего-сервера.com
```

## Типы и интерфейсы данных

В приложении используются строго определенные типы и интерфейсы TypeScript, описывающие структуру моделей данных, контракты сетевого взаимодействия и типы ошибок валидации.

### Базовые типы и интерфейсы

#### Интерфейс IProduct
Описывает структуру отдельной карточки товара (продукта) в магазине.
- `id: string` — уникальный идентификатор товара.
- `title: string` — название товара.
- `category: string` — категория товара.
- `image: string` — относительный путь или URL к изображению товара.
- `description: string` — подробное текстовое описание товара.
- `price: number | null` — стоимость товара в условных единицах. Если значение `null`, товар считается недоступным для покупки.

#### Интерфейс ICustomer
Описывает структуру данных профиля покупателя, собираемых в процессе оформления заказа.
- `payment: TPayment | "" | null` — выбранный способ оплаты (`card` или `cash`), либо `null`/пустая строка, если выбор еще не сделан.
- `address: string` — адрес доставки товара.
- `email: string` — адрес электронной почты клиента.
- `phone: string` — контактный телефон клиента.

#### Тип TPayment
Определяет допустимые значения для способов оплаты. Является объединением строковых литералов: `'card'` или `'cash'`.

#### Интерфейс TOrder
Расширяет интерфейс `ICustomer`, представляя собой полную структуру оформляемого заказа, отправляемую на сервер.
- Наследует все поля `ICustomer`.
- `items: string[]` — массив уникальных ID (`id`) товаров, которые пользователь приобретает.
- `total: number` — итоговая стоимость всех товаров в заказе.

### Типы ответов сервера и ошибок

#### Тип TServerCatalogPayload (ранее TProductListResponse)
Описывает структуру ответа сервера при запросе списка всех доступных товаров.
- `items: IProduct[]` — массив объектов товаров, доступных для отображения в каталоге.
- `total: number` — общее количество товаров на сервере.

#### Тип TServerOrderReceipt (ранее TOrderResponse)
Описывает структуру успешного ответа сервера после успешной отправки и обработки заказа.
- `id: string` — уникальный идентификатор созданного на сервере заказа.
- `total: number` — подтвержденная сервером итоговая стоимость заказа.

#### Тип TCustomerErrors
Тип для хранения ошибок валидации полей профиля покупателя. Представляет собой сопоставленный тип, ключами которого могут выступать поля интерфейса `ICustomer`, а значениями — строки с текстом ошибок.

### Интерфейсы коммуникационного слоя и отображения

#### Интерфейс INetworkProvider (ранее IApi)
Описывает контракт для низкоуровневого сетевого клиента (базового класса `Api`).
- `get<R extends object>(path: string): Promise<R>` — generic-метод для отправки HTTP GET-запросов.
- `post<R extends object>(path: string, payload: object, verb?: HttpPostMethod): Promise<R>` — generic-метод для отправки HTTP-запросов, изменяющих состояние системы.

#### Тип HttpPostMethod (ранее ApiPostMethods)
Определяет перечень доступных HTTP-методов для изменения данных на сервере. Допустимые значения: `'POST' | 'PUT' | 'DELETE'`.

#### Интерфейс IBaseLayoutFields
Описывает базовые обязательные поля для элементов отображения продуктов. Содержит поля `title` и `price`.

#### Интерфейс IViewStateConstraints
Описывает общие ограничения состояния форм отображения. Содержит строковое поле `errors` и булево поле `valid`.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

- **Model** — слой данных, отвечает за хранение и изменение данных.
- **View** — слой представления, отвечает за отображение данных на странице.
- **Presenter** — презентер (находится в файле `src/main.ts`) содержит основную логику приложения, настраивает подписки на события и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода через центральную шину событий.

### Базовый код (`src/components/base/`)

#### Класс Component<T>
Является базовым классом для всех компонентов интерфейса. 
Класс является дженериком и принимает в переменной `T` тип данных состояния, которые передаются в метод `render`.

**Конструктор:**
- `constructor(protected readonly container: HTMLElement)` — принимает ссылку на DOM-элемент, за отображение которого отвечает класс.

**Методы класса:**
- `render(data?: Partial<T>): HTMLElement` — Главный метод класса. Принимает новые данные, обновляет свойства компонента через вызовы сеттеров дочерних классов и возвращает ссылку на DOM-элемент `container`.
- `setImage(element: HTMLImageElement, src: string, alt?: string): void` — утилитарный защищенный метод для безопасной установки пути и альтернативного текста элементам `<img>`.

#### Класс Api
Содержит в себе базовую логику отправки fetch-запросов к серверу.

**Конструктор:**
- `constructor(baseUrl: string, options: RequestInit = {})` — принимает базовый адрес сервера и объект настроек. Автоматически внедряет заголовок `'Content-Type': 'application/json'`.

**Методы класса:**
- `get<T extends object>(uri: string): Promise<T>` — выполняет GET-запрос и возвращает типизированный промис с ответом сервера.
- `post<T extends object>(uri: string, data: object, method: HttpPostMethod = 'POST'): Promise<T>` — принимает объект данных, сериализует их в JSON и отправляет на сервер выбранным методом (`POST`, `PUT`, `DELETE`).
- `handleResponse<T>(response: Response): Promise<T>` — защищенный метод проверки ответа сервера. Возвращает распарсенный объект с данными или отклоняет промис с текстом ошибки из ответа.

#### Класс EventEmitter (Интерфейс IEvents)
Брокер событий, реализующий паттерн "Наблюдатель". Используется для организации обмена сообщениями и событиями между слоями данных и представления.

**Методы класса:**
- `on<T extends object>(eventName: EventName, callback: (event: T) => void): void` — регистрация обработчика (подписка) на определенное событие. Поддерживает регулярные выражения.
- `off(eventName: EventName, callback: Subscriber): void` — удаление подписки обработчика от события.
- `emit<T extends object>(eventName: string, data?: T): void` — инициализация события с оповещением всех подписчиков. Поддерживает обработку событий общего шаблона `*`.
- `trigger<T extends object>(eventName: string, context?: Partial<T>): (data: T) => void` — возвращает триггер-функцию, вызов которой автоматически генерирует событие `eventName` с объединением статического контекста и переданных данных.

### Слой данных (Компоненты моделей данных - `src/components/models/`)

#### Класс Cart
Отвечает за хранение добавленных в корзину товаров, подсчет их общего количества и стоимости. Для оптимизации поиска и удаления товаров вместо классического массива используется структура ассоциативного объекта-карты (`Record`).

**Конструктор:**
- `constructor(protected events: IEvents)` — инициализирует пустое внутреннее хранилище без прототипа через `Object.create(null)` и сохраняет экземпляр шины событий.

**Методы класса:**
- `getItems(): IProduct[]` — возвращает плоский массив всех товаров, извлеченных из объекта-хранилища.
- `addItem(item: IProduct): void` — сохраняет товар в корзину по его уникальному `id` и генерирует событие `"basket:changed"`.
- `removeItem(id: string): void` — удаляет товар из хранилища корзины по его `id` и инициирует событие `"basket:changed"`.
- `clear(): void` — полностью сбрасывает хранилище корзины до пустого объекта и генерирует событие `"basket:changed"`.
- `getTotal(): number` — вычисляет суммарную стоимость всех находящихся в корзине товаров.
- `getItemsCount(): number` — возвращает количество уникальных позиций в корзине.
- `checkItem(id: string): boolean` — проверяет, добавлен ли уже товар с указанным `id` в корзину.
#### Класс Catalog
Отвечает за сохранение, хранение и обработку списка доступных товаров витрины магазина, а также хранение информации о выбранном для просмотра продукте.

- **Конструктор:**
    - `constructor(protected events: IEvents)` — инициализирует пустые значения состояния, принимает и сохраняет экземпляр центральной шины событий для отправки уведомлений.
- **Поля класса:**
    - `_goodsList: IProduct[]` — внутренний массив всех доступных для покупки товаров на витрине.
    - `_currentActiveItem: IProduct | null` — объект товара, выбранный пользователем для превью, или `null`.
    - `events: IEvents` — ссылка на брокер событий для отправки уведомлений об изменениях.
- **Методы класса:**
    - `getItems(): IProduct[]` — возвращает изолированную копию массива всех товаров каталога витрины через `Array.from`.
    - `getTotal(): number` — возвращает общее количество товаров, находящихся в каталоге витрины.
    - `getItemById(id: string): IProduct | null` — осуществляет линейный поиск товара по его уникальному `id` и возвращает его объект (или `null`, если элемент отсутствует).
    - `setItems(items: IProduct[]): void` — обновляет массив доступных товаров и генерирует событие `"catalog:changed"`.
    - `setSelectedItem(item: IProduct | null): void` — фиксирует товар, выбранный пользователем для подробного отображения, и триггерит событие `"product:selected"`.
    - `getSelectedItem(): IProduct | null` — возвращает текущий активный (выбранный) товар.

#### Класс Customer
Отвечает за хранение, обновление и комплексную валидацию персональных профильных данных покупателя на этапах оформления покупки.

- **Конструктор:**
    - `constructor(protected events: IEvents)` — сохраняет экземпляр шины событий для оповещения системы об изменениях.
- **Поля класса:**
    - `_profile: ICustomer` — объект состояния профиля с персональными данными покупателя.
    - `events: IEvents` — ссылка на центральный брокер событий.
- **Методы класса:**
    - `set(data: Partial<ICustomer>): void` — производит частичное обновление полей профиля через безопасное слияние объектов и генерирует событие `"buyer:changed"`.
    - `get(): ICustomer` — возвращает текущую копию объекта данных покупателя.
    - `clear(): void` — сбрасывает все поля профиля покупателя до начальных пустых значений и триггерит событие `"buyer:changed"`.
    - `validate(): TCustomerErrors` — выполняет валидацию заполненности полей (проверяет способ оплаты, адрес, email и телефон) и возвращает объект с текстами ошибок для незаполненных полей.

### Слой коммуникации (`src/components/`)

#### Класс WebLarekApi
Класс-сервис высокого уровня, предоставляющий семантичные методы взаимодействия с сервером интернет-магазина «Web-Larёk».

- **Конструктор:**
    - `constructor(coreNetworkClient: INetworkProvider)` — принимает низкоуровневый сетевой клиент, соответствующий интерфейсу `INetworkProvider`.
- **Поля класса:**
    - `protected readonly restGateway: INetworkProvider` — шлюз для выполнения запросов.
- **Методы класса:**
    - `downloadCatalog(): Promise<TServerCatalogPayload>` — загружает полный список товаров с эндпоинта `/product`.
    - `sendOrderTicket(payload: TOrder): Promise<TServerOrderReceipt>` — отправляет сформированный и валидный объект заказа на эндпоинт `/order`.

### Слой представления (Компоненты интерфейса - `src/components/view/`)

#### 1. Компоненты форм и ввода данных (`/form/`)

##### BaseFormView (abstract)
Родительский абстрактный класс для управления HTML-формами. Наследуется от базового класса `Component`.

- **Конструктор:**
    - `constructor(container: HTMLFormElement, protected readonly eventBus: IEvents)` — принимает версию формы и шину событий.
- **Поля:** 
    - `formElement: HTMLFormElement` — управляемая HTML-форма.
    - `actionButton: HTMLButtonElement` — кнопка отправки формы.
    - `feedbackField: HTMLElement` — поле для вывода ошибок валидации `.form__errors`.
- **События:** 
    - При сабмите прерывает дефолтный эвент браузера и генерирует событие вида `ui:${formIdentifier}-submitted` на основе атрибута `name` формы.
- **Сеттеры:** 
    - `valid` — управляет доступностью кнопки отправки (разблокирует/блокирует).
    - `errors` — выводит текст ошибок валидации в элемент интерфейса.

##### BillingDetailsForm
Управляет формой выбора оплаты и адреса доставки доставки (шаблон `#order`). Наследуется от `BaseFormView`.

- **Конструктор:**
    - `constructor(targetContainer: HTMLFormElement, eventBus: IEvents)` — привязывает элементы управления и вешает слушатели событий.
- **Поля:** 
    - `transactionCardBtn: HTMLButtonElement` — кнопка онлайн-оплаты по карте.
    - `cashOnDeliveryBtn: HTMLButtonElement` — кнопка оплаты при получении (наличные).
    - `locationInputField: HTMLInputElement` — текстовое поле ввода адреса.
- **События:** 
    - Инициирует внешние системные события `"payment:card"`, `"payment:cash"`, `"form:address"`.
- **Сеттеры:** 
    - `payment` — переключает класс активности `button_alt-active` на кнопках выбора типа оплаты.
    - `address` — устанавливает переданное строковое значение непосредственно в инпут.

##### ContactDetailsForm
Управляет формой ввода контактных данных пользователя (шаблон `#contacts`). Наследуется от `BaseFormView`.

- **Конструктор:**
    - `constructor(targetContainer: HTMLFormElement, communicationsBus: IEvents)` — находит элементы разметки и вешает слушатели ввода.
- **Поля:** 
    - `emailBoxField: HTMLInputElement` — поле ввода адреса электронной почты.
    - `telephoneBoxField: HTMLInputElement` — поле ввода телефона.
- **События:** 
    - При вводе данных пользователем генерирует события `"form:email"` и `"form:phone"` с объектом вида `{ value: string }`.
- **Сеттеры:** 
    - `email` — для программного заполнения инпута почты.
    - `phone` — для программного заполнения инпута телефона.

#### 2. Компоненты элементов и карточек товаров (`/productCards/`)

##### BaseCatalogItem (abstract)
Базовый абстрактный класс для отображения названия и стоимости продукта. Наследуется от базового класса `Component`.

- **Конструктор:**
    - `constructor(targetContainer: HTMLElement)` — принимает и валидирует базовые узлы карточки.
- **Поля:** 
    - `headerNode: HTMLElement` — заголовок карточки товара (`.card__title`).
    - `costNode: HTMLElement` — контейнер для вывода стоимости (`.card__price`).
- **Сеттеры:** 
    - `title` — устанавливает текстовый заголовок карточки.
    - `price` — если значение цены `null` или `undefined`, выводит текст **"Цена не указана"**, иначе выводит число с суффиксом `"синапсов"`.

##### CatalogGridCard
Карточка товара для отображения в общей сетке витрины магазина (шаблон `#card-catalog`). Наследуется от `BaseCatalogItem`.

- **Конструктор:**
    - `constructor(targetContainer: HTMLElement, clickHandler?: { onClick: () => void })` — вешает обработчик клика на весь контейнер карточки.
- **Поля:** 
    - `badgeNode: HTMLElement` — тег категории товара (`.card__category`).
    - `previewImageNode: HTMLImageElement` — изображение товара (`.card__image`).
- **Логика и Сеттеры:** 
    - `category` — динамически навешивает CSS-класс цвета категории на основе глобального реестра `UI_CATEGORY_STYLE_REGISTRY`.
    - `image` — подставляет относительный путь к CDN сервера.

##### DetailedItemView
Карточка расширенного детального просмотра товара внутри модального окна превью (шаблон `#card-preview`). Наследуется от `BaseCatalogItem`.

- **Конструктор:**
    - `constructor(targetContainer: HTMLElement, eventCallbacks: { onClick: (evt: MouseEvent) => void })` — привязывает обработчик клика непосредственно к целевой кнопке.
- **Поля:** 
    - `categoryTagNode: HTMLElement` — элемент категории товара.
    - `bodyTextNode: HTMLElement` — подробное описание товара (`.card__text`).
    - `actionButtonNode: HTMLButtonElement` — кнопка действия (`.card__button`).
    - `visualNode: HTMLImageElement` — картинка товара.
- **Сеттеры:**
    - `description` — устанавливает подробное текстовое описание продукта.
    - `category` — задает текстовое название категории товара.
    - `image` — меняет путь к картинке с учетом базового URL.
    - `buttonText` — меняет надпись на кнопке ("Купить", "Удалить из корзины" и т.д.).
    - `buttonDisabled` — полностью блокирует кнопку взаимодействия, если товар бесценен (цена равна `null`).

##### BasketRowItem
Отображение строки товара в списке внутри корзины (HTML-шаблон `#card-basket`). Наследуется от `BaseCatalogItem`.

## Список событий приложения (Presenter)

Управление состояниями и синхронизация слоев осуществляются в `src/main.ts` через подписки на события центральной шины:

### События уровня моделей (Model Events)
- `catalog:changed` — данные витрины успешно обновлены или загружены из сети. Вызывает рендер карточек товаров и обновление главной галереи.
- `product:selected` — зафиксирован выбор товара пользователем. Вызывает открытие модального окна с карточкой превью и динамической кнопкой ("Купить" / "Удалить из корзины" / "Недоступно").
- `basket:changed` — состав корзины изменен (добавление или удаление). Вызывает обновление счетчика шапки, пересчет сумм и обновление списка строк в виджете корзины.
- `buyer:changed` — изменены профильные данные покупателя. Вызывает валидацию и обновление состояния кнопок/ошибок в формах заказа.

### События уровня интерфейса (UI / View Events)
- `action:catalog-item-clicked` — пользователь выбрал товар в галерее, кликнув по карточке.
- `ui:open-basket-requested` — клик по кнопке корзины в шапке сайта. Открывает оверлей корзины.
- `basket:submit` — клик по кнопке оформления в корзине. Переключает оверлей на форму доставки (`BillingDetailsForm`).
- `payment:card` / `payment:cash` — выбор соответствующего метода оплаты в форме.
- `form:address` / `form:email` / `form:phone` — ввод пользователем текста в соответствующие инпуты форм.
- `ui:order-submitted` — отправка первой формы. Переключает оверлей на форму контактов (`ContactDetailsForm`).
- `ui:contacts-submitted` — финальная отправка заказа. Собирает полный объект заказа `TOrder`, отправляет его на сервер через `WebLarekApi`, а при успешном ответе очищает корзину/модель покупателя и выводит окно успеха.
- `overlay:popup-dismissed` — модальное окно было закрыто пользователем (клик по фону или крестику).
- `checkout:success-acknowledged` — закрытие окна успешной оплаты по кнопке "За покупками!".
